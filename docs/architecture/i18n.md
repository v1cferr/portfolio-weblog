# Internationalization

- Locales: `en-us` (default), `pt-br`, `zh-cn`, always prefixed (`/en-us/...`),
  as in v1. Unprefixed paths redirect using the `NEXT_LOCALE` cookie, then
  `Accept-Language`, then `en-us`.
- The locale is read through `next/root-params` (next-intl's recommended setup
  on Next 16). Route handlers pass it explicitly.

## Interface strings

`apps/web/messages/<locale>.json`. English is the reference catalogue
(`AppConfig` types every key). `pt-br` is complete. `zh-cn` contains only the
strings reviewed in v1; every missing key falls back to English at load time. No
machine translation is shipped as final.

## Editorial content

Each localized field picks the requested locale, then English, then any other
available one. When a page shows text in a different locale than requested, it
renders a visible notice and marks the text with the right `lang` attribute.
Articles are separate files per locale; a missing translation serves the
original with the notice, its canonical URL points at the original, and
`hreflang` lists only real translations.

To add a translation, add the locale's key to the YAML field or a new
`<locale>.mdx` file.
